## Task A2: Understand Runtime Binding & The Virtual Table

### 1. Early vs Late Binding (A2.1)
- **Early Binding (Static)**: For non-virtual member functions, function call addresses are resolved at compile/link time based purely on the static pointer type (`Base*`). Fast, zero indirection, but cannot vary with runtime instance type.
- **Late Binding (Dynamic)**: For `virtual` functions, resolution is deferred to runtime. The compiler emits code to dereference the object's `vptr`, locate the function pointer in the `vtable`, and dispatch to `Derived::vfunc`.

### 2. Virtual Table (vtable) Architecture (A2.2)
Every class containing virtual functions has a static `vtable` generated by the compiler containing function pointers to virtual methods. Each instance contains an implicit hidden pointer (`vptr`, 8 bytes on 64-bit architectures) pointing to that vtable.
